# agent-delegation

把 AI Agent 当「外包助理」管理的委派方法论：战场已从"做一个爆款产品"转移到"把 Agent 塞进真实工作流、让用户真的愿意把事交给它"——胜负手是低门槛 + 信任口碑，不是模型多强。软件靠功能清单，助理靠**授权、验收与复盘**。

一句话：**别追爆款 Agent，挑一件你每周做三次的活，让它先做到 80 分。剩下的 20 分，正是你未来真正的门槛。**

## 方法论底座（七表象一根骨头）

- 入口迁办公/PC → 只有专业场景才有完整、可计价的工作流
- 不装 App、短信/邮件唤醒 → 降低门槛，让"使用"先发生
- 做金融收佣金 → 嵌入交易闭环才收得到钱，订阅费撑不起价值
- 成功归功于用户 → Agent 价值由用户用多深决定，不由参数决定
- 强调口碑门槛 → 同质化混战里，信任是唯一的差异化
- 真瓶颈：易用性已不是问题，"让用户相信它、愿意授权它"才是最难的坎
- 终局变量：用户体验、进入门槛——市场正在集体奖赏"零门槛的服务"

## 解决什么

| 痛点 | 本技能的做法 |
|---|---|
| 哪些工作能交给 Agent | 任务分层 A/B/C：A 全自动（错得起改得回）/ B 半自动（Agent 起草你拍板）/ C 禁区（情感/对外承诺/资金合规永远留给人）；归层判问 30 秒一层（可逆?涉信任?30s 拍板?）；"拆到能拍板为止" |
| 试点选什么任务 | 单点切入：排序矩阵（频次×低风险×可验证）+ 可交接四条件（输入结构化/结果可验证/出错可回滚/频次≥3 次/周，缺一条先补条件）+ 两周试点只看两个数（成功率≥80%、省分钟≥50%） |
| Agent 为什么总用不起来 | 零门槛硬线：触发=你本来就要做的动作（转发邮件/群里 @）；为 Agent 新建入口=试点失败信号；"短信唤醒"的全部意义 |
| 权限怎么给才安全 | 信任阶梯 L1 只读→L2 可写→L3 可代发：每级达标证据（连续周数+零事故）+回滚点（必须实测可用，5 分钟判据）+人工复核点（100%→10% 抽检的降档条件）；翻车降级流程（事故 1-3 级，降级=证据作废重跑）；L3 安全四件套（草稿可见/延迟发送/白名单渠道/频次上限） |
| 跑通了怎么变值钱 | 沉淀三件套（输入模板+提示词+验收清单）+ SOP 一页纸 + "别人跑"验收（没跑过的人照着跑通≥3 次才是真资产）；对团队=效率/对产品=口碑/对个人=谈价本钱 |
| 自动化翻车赔不起 | 风险硬阈值：算清"错一次赔多少"+红线写进配置（非"我记得"）+升级时重算；"佣金逻辑反过来收割你"三个识别信号（创造需求/红线附近动作变多/C 区擦边自动化） |

## 安装

复制本目录到 `~/.agents/skills/`（或你的 Skill 加载路径）即可。

## 自检

```bash
python scripts/validate.py tests/sample_good.json   # 必须 exit 0
python scripts/validate.py tests/sample_bad.json    # 必须 exit 1
```
