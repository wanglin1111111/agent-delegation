# 任务分层实操：A/B/C 归层判问与拆解

> 核心：A 全自动（错得起、改得回）/ B 半自动（Agent 起草你拍板）/ C 禁区（永远留给人）。**先盘点再谈工具**——分层没做完就上 Agent，等于把权限决策留给事故。

## 一、归层判问（按顺序，30 秒一层）

```
对每个任务，按顺序问：
Q1 出错后果可逆吗？
  可逆（删掉重来/改一下/撤回）→ 继续 Q2
  不可逆（发出去收不回/钱出去了/话说了）→ 最高 B 层（Agent 起草你发出），
    且若涉 Q2 则直接 C
Q2 涉及对外信任/资金/合规吗？
  对外承诺、合同、报价、资金操作、合规申报、情感判断（安慰/道歉/挽留/冲突）
  → C 禁区（无讨论，Agent 最多做素材准备）
Q3 结果我能 30 秒内拍板吗？
  能 → 候选 A 或 B（看下一条分界）
  不能（要开会/要查很久/要多人确认）→ 任务没拆干净，先拆
A/B 分界：
  我需要逐条看过才放心吗？要 → B；抽检就够 → A
  抽检的标准：错一条的代价 ≤ 重做一次的成本 → 可以 A
```

## 二、每层典型任务清单（判据 + 常见误判）

### A 全自动（错得起、改得回）

| 典型任务 | 为什么是 A | 常见误判 |
|---|---|---|
| 信息汇总（行业日报/数据周报） | 错了=下次改，受众内部，无承诺 | 汇总里含"建议"→ 建议部分降 B（判断性内容抽检不够） |
| 格式整理（纪要排版/表格清洗） | 纯转换，错了肉眼 3 秒发现 | "整理"里夹了"归类/标注"→ 标注是判断，降 B |
| 初稿生成（内部文档/周报初稿） | 初稿本来就要人改 | "初稿直接发给领导"→ 发送动作是 B，生成是 A（两个动作分开归层） |
| 会议纪要（录音→纪要） | 纪要错了可重录/可追认 | 纪要含"行动项指派"→ 指派降 B（指派是对人的承诺） |

### B 半自动（Agent 起草，你拍板）

| 典型任务 | 为什么是 B | 升 A 的条件 |
|---|---|---|
| 邮件回复 | 对外但可撤回（多数邮箱）、内容需语境判断 | 模板化程度高（客服标准答复）+ 连续 4 周抽检 0 错 → 该类邮件可升 A 代发（进 L3 阶梯评估） |
| 方案初稿 | 方案涉判断，拍板权必须在你 | 初稿只给你自己看（不进评审）→ 生成部分 A，评审意见整理 B |
| 数据核对 | 核对结论要对下游负责 | 核对只产"差异清单"（你判断）→ 跑数部分 A，差异判定 B |
| 对外内容初稿（推文/公告） | 对外+涉品牌 | 内部预审核流程完整 + 连续 8 周 0 返工 → 可进 L3 评估 |

### C 禁区（永远留给人）

| 典型 | 为什么是 C | Agent 的边界（素材准备可以） |
|---|---|---|
| 情感判断（安慰/道歉/挽留/冲突处理） | AI 模仿不了人的情感与使用习惯；说错=信任永久损伤 | 可以整理"对方情绪要点+历史沟通记录"给人看（只读素材），不出草稿 |
| 对外承诺（报价/交付期/合同条款） | 不可逆+涉信任+涉资金 | 可以列"历史报价区间+约束条件清单"给人参考，不出具体数字 |
| 资金与合规（付款/审批/申报） | 错一次直接损失+法律责任 | 可以备齐材料清单/检查合规项是否齐备（核对，不操作） |
| 人事相关（绩效/解雇/晋升沟通） | 情感+不可逆+涉信任 | 可以汇总数据事实（不排序、不评价、不出措辞） |

**C 区的纪律**：C 区任务出现在任何自动化计划里 = validate.py 直接拦。"Agent 帮我拟个道歉信"也是 C——拟信本身是情感表达，素材准备和表达是两个动作，后者永远是人。

## 三、"拆到能拍板为止"的任务拆解法

Q3 答"不能 30 秒拍板"时，不是放弃这个任务，是拆：

```
例：「准备季度客户汇报」
  不能 30 秒拍板（要开会、要多人确认）
拆：
  1. 拉数据（A：错得起，错了重拉）
  2. 生成汇报初稿（B：你拍板内容取舍）
  3. 预判客户会问的 5 个问题（B：Agent 起草你改，判断在你）
  4. 现场演讲与临场应答（C：情感+对外承诺，永远你）
拆完的判据：每个子任务都能单独回答 Q1-Q3
拆不动的子任务 = 它本来就是一个"会"不是"任务"，移出自动化范围
```

## 四、分层结果表模板（每周盘点用，与 work-tri-layer 三层盘点合并做）

```markdown
# 任务分层 <周次>
| # | 任务 | 频次/周 | 归层 | Q1 可逆 | Q2 涉信任/资金 | Q3 30s拍板 | A/B 分界 | 备注 |
|---|---|---|---|---|---|---|---|---|
| 1 | 行业日报 | 5 | A | 可 | 否 | 能 | 抽检够 | 已跑 L2 |
| 2 | 客户邮件回复 | 15 | B | 撤回 | 边界 | 能 | 逐条过 | 标准答复类候选升 A |
| 3 | 客户投诉安抚 | 2 | C | 不可 | 是 | — | — | 禁区，Agent 只备素材 |
## 盘点结论
A 层共 __ 项 / B 层 __ 项 / C 层 __ 项
本周试点候选（从 A/B 里选，按 pilot-acceptance 的排序）：__
## 与上周差异
新归层：__（为什么从 X 变 Y）
```

**分层是动态的**：任务归层会随信任阶梯升降（B→A 升级）或随业务变化（新任务进来重归层）。每周盘点时重点看"边界任务"（备注里写"候选升/降"的），它们是分层表里唯一需要动的行。
