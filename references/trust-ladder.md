# 信任阶梯细则：逐级放权、回滚点、复核点、翻车降级

> 核心：**小权限起步 → 达标后升级：先只读 → 后可写 → 最后才可代发。每一级都设回滚点和人工复核点。信任不是一次性给的，是被结果喂出来的。** 阶梯的本质是把"信任"拆成可验证的小块——每一级的"升级资格"都是一份证据，不是一次表态。

## 一、三级权限边界（每级 Agent 能碰什么、绝不能碰什么）

### L1 只读

```
能碰：读数据 / 读文档 / 汇总 / 起草（产出物在草稿区，不落地任何真实位置）
绝不能碰：写入任何真实位置 / 发送任何消息 / 触发任何外部动作
适用任务：全部 A 层 + B 层的"生成"部分
达标证据（升 L2）：
  [ ] 连续 2 周成功率 ≥80%（按 pilot-acceptance 的口径，重试成功也算失败）
  [ ] 零事故（"事故"= 你发现产出物已经污染了真实位置，而非"质量不够好"）
  [ ] 回滚预案写下来（L2 要真写东西了，"错了怎么办"必须先有答案）
```

### L2 可写（内部）

```
能碰：写入内部产物（文档库/表格/内部系统/工单内部字段）
绝不能碰：任何对外发出 / 任何涉资金操作 / C 禁区任何环节
适用任务：A 层全量 + B 层"你拍板前"的内部落稿
达标证据（升 L3）：
  [ ] 连续 4 周零"改错未回滚"（错了且回滚失败的次数 = 0）
  [ ] 回滚流程实测过（故意制造一次错误写入，5 分钟内撤回成功——记录时间）
  [ ] 人工复核点配置定稿（哪些写入必须人过一眼，见下）
  [ ] B 层任务连续 4 周"人审后返工率 <10%"
  [ ] 红线阈值已配置（见 asset-and-risk：涉金额/额度的写入额度上限）
L2 的硬要求：回滚点必须"实测可用"——没实测过的回滚是想象中的回滚。
  测试方法：D 日做一次真实错误写入（无害内容），走一遍撤回，计时。
  撤回 >5 分钟 → 回滚不可用 → 不能升 L3，先修回滚（或该写入位置加"人确认才提交"）
```

### L3 可代发（对外）

```
能碰：对外发出（发邮件/发评论/提交对外工单/发布内容）
绝不能碰：C 禁区（情感/对外承诺/资金合规）——任何级别都不碰
适用任务：B 层里"模板化程度高 + 连续 8 周抽检 0 返工"的类别
  （例：客服标准答复类邮件——注意是"类别"，不是"某封邮件"）
达标证据（维持 L3，不是"升到 L3 就完了"）：
  [ ] 每周抽检 ≥10%（连续 4 周 100% 人审 → 稳定后可降到 10% 抽检）
  [ ] 抽检中发现的错误率 <5%（≥5% = 降回 100% 人审）
  [ ] 零 L3 事故（对外发错且未撤回 = L3 事故，一次即降级）
L3 的安全设计（四件，缺一不升）：
  1. 草稿可见：发出的内容在发出前有 30 秒-5 分钟的可见窗口（可取消）
  2. 延迟发送：非紧急的对外消息统一延迟 15 分钟发出（给你反悔窗口）
  3. 白名单渠道：只能发到白名单里的渠道/收件人（新渠道必须人工加白）
  4. 额度/频次上限：单日对外动作 ≤N 次（超了自动停，等人确认）
```

## 二、回滚点设计（什么算"回滚可用"）

```
回滚可用的三个判据（缺一 = 不可用）：
  [ ] 可发现：错误写入/发出后，有明确途径找到它（不是"翻半天找记录"）
      - 内部写入：系统有操作日志/版本历史
      - 对外发出：有撤回功能（邮件 2 分钟内/社交平台 24 小时内，按渠道实测）
  [ ] 可撤销：找到后能撤回或覆盖（不是"只能发一条更正"——更正≠回滚，
      更正是补救，回滚是恢复原状；两者都要会，但回滚是硬要求）
  [ ] 可计时：从发现到恢复原状 <5 分钟（实测，不是估计）
每级的回滚点落点不同：
  L1：草稿区产物 → 删除即可（天然可回滚，风险最低）
  L2：内部系统 → 版本历史/日志 + 撤销操作（须实测）
  L3：对外渠道 → 撤回功能（各渠道能力差异大，升 L3 前逐渠道实测）
      渠道没有撤回功能（如某些 IM）→ 该渠道不进 L3，或该渠道永远 100% 人审
回滚记录（每次翻车必须留档）：
  日期 | 级别 | 错误内容 | 发现途径 | 回滚耗时 | 是否 5 分钟内 | 根因
  用途：月度复盘时看"回滚耗时趋势"（变长 = 系统变更过，回滚点失效了）
```

## 三、人工复核点配置（100% → 抽检的降档条件）

```
复核点不是"要不要看"，是"看多少"——按风险与稳定性两个轴配：
  轴 1 风险（不可逆性）：对外 > 对内；涉资金/承诺 > 纯内部
  轴 2 稳定性（历史错误率）：新配置 <2 周=不稳；>4 周且错误率 <5%=稳
配置矩阵（默认值，可按团队风险偏好调，调了要记录）：
  L2 内部写入：稳 → 抽检 10%；不稳 → 100%
  L3 对外发出：稳 → 抽检 10%；不稳 → 100%
  任何涉金额/额度的动作：永远 100%（不看稳定性，红线任务不降档）
  C 禁区：100% 人工（Agent 连草稿都不出，只备素材）
降档（100%→抽检）必须满足：
  [ ] 该配置连续 4 周错误率 <5%
  [ ] 回滚点实测可用（最近一次实测 <30 天）
  [ ] 降档后第一周错误率不反弹（反弹 = 立即回 100%，且下季度才允许再申请降档）
升档（抽检→100%，即收紧）的触发：
  任何一次 L3 事故 / 抽检错误率 ≥5% / 回滚实测失败 → 立即回 100%，不等周
```

## 四、翻车降级流程（"不是注意一下"）

```
翻车分级（按后果，不按"严不严重"的感觉）：
  事故 1 级（内部错误，已回滚，5 分钟内）：
    记录 + 补根因；级别不变；复核点收紧一档（抽检→100%，持续 2 周）
  事故 2 级（内部错误未回滚成功 / 对外错误但已撤回）：
    降回上一级，重跑该级达标证据（连续周数清零）
    例：L3 翻车 → 回 L2，重新攒 4 周证据才能再申请 L3
  事故 3 级（对外错误未撤回 / 涉资金错误 / C 区被碰）：
    降到 L1，且该任务类别 30 天内不得再申请升级
    C 区被碰 = 配置事故（白名单/红线失效），先修配置再谈升级
  任何级别翻车：
    [ ] 24h 内写根因（不是"下次注意"，是可执行的配置修改）
    [ ] 根因修完才能申请恢复级别（未修根因的恢复 = 下次还翻）
    [ ] 翻车记录进资产库（与 asset-and-risk 的 SOP 关联：翻过的车写进 SOP 的"翻车了怎么办"）
信任是被结果喂出来的——对称地，它也是被事故拿走的。降级不是惩罚，是证据作废重跑。
```

## 五、阶梯节奏参考（不是 KPI，是"太快=危险"的警戒线）

```
健康节奏（参考，因人而异，任务不同节奏不同）：
  L1 → L2：2-4 周（试点跑通 + 2 周稳定）
  L2 → L3：4-8 周（回滚实测 + 4 周证据 + L3 四件套安全设计就绪）
  L3 内扩类别：每新增一个 B 层类别，该类别单独走一遍"L3 评估"
      （不是"已经 L3 了所以新类别直接发"——类别是独立的信任单元）
警戒线（超过 = 你在跳级，停）：
  ✗ 两周从 L1 直接申请 L3（中间证据都没攒）
  ✗ 用"老板/客户着急"当跳级理由（急=风险溢价，不是信任）
  ✗ 把"Agent 自己说它没问题"当证据（证据只能是外部可查的运行记录）
```
